# Patched AT&T Z999 images — October 17, 2026

[Download the image assets](https://github.com/channelramble/ZTE-Axon-M-Flash-Tool/releases/tag/att-z999-los23.2-test25-20261017)

These are the actual tested artifacts from the AT&T Axon M port investigation,
published at the owner's explicit request. They target one unlocked **AT&T Z999,
fujisan, eMMC, stock B37 bootloader/firmware**. This is an experimental diagnostic
adaptation of the developer's unofficial LineageOS 23.2 / Android 16 release.
It boots, but does not have production security or complete hardware support.

## Downloads and targets

| Asset | Purpose and target |
|---|---|
| `lineage-23.2-fujisan-ATT-test20-boot.img` | Android kernel/ramdisk; signed for **boot**. Use with either patched system below. |
| `lineage-23.2-fujisan-ATT-test24-recovery.img` | Lineage recovery; signed for **recovery**. Native recovery boot and factory reset verified. |
| `lineage-23.2-fujisan-ATT-test23-system-vanilla.img.gz` | Patched LOS system without GApps; decompress to raw **system** image. Full Android boot verified by ADB and owner. |
| `lineage-23.2-fujisan-ATT-test25-system-gapps.img.gz` | Same patched system plus MindTheGapps Android 16 ARM64; decompress to raw **system** image. Complete installation/readback verified; owner confirms Android boots. |
| `twrp-3.7.0-fujisan-ATT-test18-BOOT-target.img` | Optional tested TWRP control, signed for **boot**, NOT recovery. It occupies the same partition as LOS boot; restoring LOS boot is necessary to return to Android. |
| `SHA256SUMS` | Checksums of downloaded image files. |
| `release-manifest.json` | Exact sizes, hashes, targets, and decompressed-system hashes. |

The system files are gzip-compressed **raw ext4 images**, each expanding to
6,979,321,856 bytes. They are not Android sparse images and are not recovery
sideload/update ZIPs. Choose one system variant. Decompress before raw-image
installation; never write gzip bytes directly to a partition. For example:

```sh
shasum -a 256 -c SHA256SUMS
gzip -dk lineage-23.2-fujisan-ATT-test25-system-gapps.img.gz
shasum -a 256 lineage-23.2-fujisan-ATT-test25-system-gapps.img
```

Compare the final hash with `uncompressed_sha256` in the manifest. Use the same
commands with the vanilla filename if choosing that variant. Have at least
7 GB free in addition to the downloaded package for each decompressed system.
The checksum file lists all five image downloads; verify individual manifest
entries if downloading only a subset.

These assets are not a universal installer. Do not use the original ROM ZIP or
its firmware ZIP to install over this adaptation: that can overwrite the
AT&T-specific changes. Do not flash China/DoCoMo bootloader firmware. Verify the
actual device GPT and the intended partition before any image write; the old
Windows flash-tool release does not automatically implement this LOS install.
The documented successful clean install uses F2FS userdata and the repaired
Lineage recovery. A fresh device installation still needs an appropriate
user-authorized data migration/reset plan. No userdata image is supplied.

These exact tested images retain a device-specific cache-filesystem UUID pin
in the diagnostic log persister. On another phone, that logger may refuse to
persist logs; the Test24 recovery persister is disabled. This is not a portable
configuration or a claim of universal compatibility. No account/authentication
key is included by that diagnostic pin.

The TWRP file is the exact boot-tested artifact, including its `/boot` signature.
Renaming it does not make it a recovery-target image. We did not manufacture a
new untested recovery-signed TWRP variant just for this release. TWRP and LOS
recovery use their own source DTBs; they are not interchangeable with LOS boot.

## Total work completed

1. **Recovered reliable device access.** Established remote MacBook USB/EDL
   access, pinned the correct eMMC Firehose programmer and ADB version, mapped
   the GPT, preserved rollback material, and verified writes by full readback.
2. **Made the AT&T bootloader accept the 4.4 images.** Found its insufficient
   device-tree expansion space; added 8 KiB slack per DTB, preserved each source
   image's DTBs, reserved the AT&T shared-memory region, and signed images for
   their intended boot/recovery targets.
3. **Got the kernel and USB through startup.** Iterated with early RAM/pstore
   logs and controlled checkpoints, isolated incompatible QSEE/QCE and firmware
   initialization, resolved the USB supplier dependency, restored normal late
   kernel cleanup, and enabled reliable adb-only peripheral operation. MTP is
   disabled in the tested recovery setup.
4. **Booted modern recovery.** Obtained working TWRP 3.7.0 and LOS 23.2 recovery
   on their 4.4 kernels. Verified the actual recovery partition through BCB
   entry and automatic command clearing.
5. **Got Android rendering and completing boot.** Installed the AT&T GPU zap
   firmware, adapted init/USB/mount behavior, worked around the unavailable
   Gatekeeper service and optional GPU-memory-accounting crash, then restored
   the USB port HAL that had blocked framework boot completion.
6. **Verified the working UI.** Android reports `sys.boot_completed=1`; seven
   observations over 185.767 seconds retained the same system_server process
   with the USB HAL running. The owner confirmed single-screen use when folded
   and one display spanning both screens when unfolded.
7. **Repaired native factory-reset handling.** Removed diagnostic recovery
   command-line arguments that suppressed BCB/cache operation requests,
   restored cache/data fstab entries, tested native F2FS formatting in RAM,
   and verified a real owner-authorized data/cache reset.
8. **Installed and verified GApps.** Ran the checksum-pinned original
   MindTheGapps installer once. Verified all 36 intended Google payload files,
   27 retained AT&T files, permissions/labels and addon.d content; then verified
   the entire system and unchanged boot/recovery/misc/GPT. The owner confirms
   both Android and recovery boot afterward.
9. **Investigated button entry.** Confirmed independent physical Volume Up,
   START-menu/PMIC, and BCB routes in the AT&T bootloader. The current factory
   mode flag is normal. Direct Volume Up timing/power-reason behavior remains
   unresolved; no bootloader patch was made.
10. **Published the investigation.** Preserved findings, patching and diagnostic
    source, review records, checksums, offline helpers and tests. This release
    adds the actual patched images, which were previously kept private.

## Working results and remaining limits

- **Works on the tested unit:** Android startup/UI, graphics, owner-confirmed
  folded single-screen and unfolded spanning, adb, TWRP boot, LOS recovery boot,
  native factory reset, and verified GApps installation.
- **Recovery entry:** owner reports both Android and recovery can boot through
  START; direct Power/Volume Up entry remains unverified. Do not interpret a
  working image as proof that all bootloader menu/button paths are repaired.
- **Security remains diagnostic:** permissive SELinux, root unauthenticated adb,
  unavailable QSEE-backed Gatekeeper/secure credentials. This is not a secure
  daily-use build; GApps installation does not establish Play certification,
  Google sign-in success, or app compatibility.
- **Hardware remains incomplete:** camera-daemon crashes are known. Modem/calls,
  audio/ADSP, sensors, fingerprint, video acceleration, Wi-Fi/Bluetooth, charging,
  suspend, thermals and battery life need repair or further validation. Several
  incompatible providers remain disabled. A successful boot does not establish
  those features work.
- **Display feature gap:** stock ZTE mirror/independent-app screen modes are not
  implemented by this upstream port. Existing single/span behavior and the
  folded Main screen switch tile remain intact.
